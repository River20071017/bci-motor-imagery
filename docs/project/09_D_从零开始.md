## 4. 你应该看懂的代码

先看 `examples/demo_archive.py`，再看 `src/eeg_app/outputs/archive.py` 和 `sinks.py`。

- DecisionFrame 就是一张判断单，使用队友的 `to_json()` 原样写入。
- IntentEvent 是一整次动作，使用队友的 `to_dict()` 写 CSV；此模块不推测起止时间。
- RuntimeEvent 是程序发生的事情，如 pause、finish、write_error。
- 后台队列让写文件不占用绘图线程；满队列会失败，不会悄悄扔掉记录。
- 每隔不超过 1 秒调度一次 flush + fsync；繁忙磁盘本身的写入时延仍须实测。
- summary 起初就是 completed=false，正常排空并关闭后才改为 true。
- 不知道的源文件 SHA、模型信息不能编造。合成例明确没有源文件；真实联调由 A 提供。

## 5. 给 A/C 的接入说明

这里导出的是具体 `JsonlResultSink`，**没有**修改 contracts 或新增 ResultSink Protocol。
冻结契约要求先有实际实现，不提前抽象，接入者直接使用以下方法。

```python
from eeg_app.outputs import ArchiveWriteError, JsonlResultSink

# metadata 至少含 recording_id/model_id/pipeline_version/config_hash 四个字符串。
# 真实组装入口还须提供 app_version、config、dependencies、source_files（含 SHA-256）。
sink = JsonlResultSink(output_root, session_id, metadata)
sink.submit(decision_frame)       # 与送给 C 的是同一个 frozen 对象
sink.submit(closed_intent_event)  # 已结束，且引用的决策必须先入队
sink.submit(runtime_event)

# 正常 EOF 或正常用户停止：先停止生产、关闭未结束动作事件，再排空存档。
sink.close(completed=True, reason="finished")
# 用户正常停止可用 reason="stopped"；completed 表示存档完整，不代表算法通过。
```

序号须从 0 连续递增，不能只保存有效类别。一个会话固定一条 recording 和一个模型/配置。
切换记录或模型要新建会话目录；同名目录会被拒绝，绝不覆盖。

C 在 GUI 主线程定时读取 `sink.status`：

| state | 显示建议 | A 应如何处理 |
| --- | --- | --- |
| writing | 正在保存 | 正常生产 |
| closing | 正在写完剩余记录 | 停止生产，等待工作线程完成 |
| closed + completed=true | 保存完成，并显示 directory | 可打开会话目录 |
| failed | 保存失败，显示 error | 立即停止供数/暂停会话并停止动作反馈 |

`submit()` 成功只表示入队；不能据此显示“保存成功”。
`submit()` / `check_error()` / `close()` 会抛 ArchiveWriteError，调用方必须处理。
后台线程不操作 Qt，也不会自行调用尚未实现的 A 会话控制器。
为了不阻塞 GUI，`close()` 应由 A 的控制/工作线程调用，再用 Qt 信号回传结果。
构造阶段也会等待目录初始化，应在工作线程建立 sink。

磁盘失败可能连 runtime.jsonl 都无法追加：此时以内存 `failed/error` 和原有
completed=false 为准，不承诺在故障磁盘上还能写出 write_error。
错误的实时暂停/界面提示需在第 2 步与 A/C 接通；当前 GUI 尚未调用本模块。
