# 架构总览：应用层与底层实现

> 一句话：**`eeg_core` 是底层，只做纯计算；`eeg_app` 是应用层，只做 IO/时序/界面；
> `training` 是离线组合层，纯管线只依赖 core，入口 `main` 负责把文件变成记录。**
>
> 依赖方向只能向下：`app → core`、`training → core`。**core 永远不 import app/training。**

## 1. 三层是什么

```text
┌──────────────────────────────────────────────────────────────┐
│ eeg_app（应用层）                                             │
│ sources：MNE 多格式读取、通道别名、重采样、Recording、ReplaySource │
│ runtime：会话状态机、环形缓冲、队列（待实现）                  │
│ ui：Qt 窗口、波形、火柴人（待实现）                            │
│ outputs：decisions.jsonl / events.csv / manifest（待实现）     │
└───────────────────────────┬──────────────────────────────────┘
                            │ 可以依赖
┌───────────────────────────▼──────────────────────────────────┐
│ eeg_core（底层）                                              │
│ contracts：EEGChunk / WindowRange / DecisionFrame / ModelSpec │
│ processing：质量、参考、因果滤波、分窗、18 维特征              │
│ decoding：LDA 数组、模型包加载、六状态决策                     │
│ version：PIPELINE_VERSION                                     │
└───────────────────────────▲──────────────────────────────────┘
                            │ 只依赖 core
┌───────────────────────────┴──────────────────────────────────┐
│ training（离线训练组合层）                                    │
│ pipeline.py：纯，吃 RecordingLike → 18 维窗                    │
│ train.py / evaluate.py：入口，main 里加载 EDF                  │
│ mock.py：纯 EEGChunk/Recording mock，不读文件                 │
└──────────────────────────────────────────────────────────────┘
```

### 底层（`src/eeg_core`）

| 包 | 职责 | 允许依赖 |
| --- | --- | --- |
| `contracts` | 输入/输出/事件/模型规格；frozen dataclass | 标准库、numpy |
| `processing` | 质量检查、参考、Butterworth、窗、特征 | 标准库、numpy、scipy、contracts |
| `decoding` | LDA、模型包、推理、决策状态机 | 标准库、numpy、sklearn、contracts |
| `version` | `PIPELINE_VERSION` | 无 |

**禁止**：`mne`、`PySide6`、`argparse`、`Path.read_text()`、`threading`、`eeg_app`、`training`。
这些都属于 IO/编排，不属于“信号怎么算”。

### 应用层（`src/eeg_app`）

| 包 | 职责 | 典型依赖 |
| --- | --- | --- |
| `sources` | MNE 读取（按扩展名分派）→ `Recording`；1 倍速回放 → `EEGChunk` | mne、threading、time、contracts |
| `runtime` | 会话状态、缓冲、队列、暂停/停止（待实现） | contracts、processing |
| `ui` | 波形、预测轨、火柴人（待实现） | PySide6、pyqtgraph |
| `outputs` | JSONL/CSV/manifest 写入（待实现） | contracts、json、pathlib |

**应用层可以做**：读文件、开线程、碰时钟、画界面、写文件。
**应用层不应该做**：自己写滤波/特征/分类器；这些必须调用 `eeg_core`，否则训练和运行时两套实现。

### 离线训练层（`training`）

| 文件 | 层级 | 说明 |
| --- | --- | --- |
| `pipeline.py` | 纯管线 | 只依赖 `RecordingLike`、`eeg_core.processing`、`contracts`；不 import `eeg_app` |
| `mock.py` | 纯 mock | 生成 `EEGChunk` 流 / `MockRecording`；只依赖 `contracts` + numpy |
| `train.py` | 入口/组合根 | `main()` 里 `_load_recording()` 才 import `eeg_app.sources.input` |
| `evaluate.py` | 入口/组合根 | 同上 |
| `README.md` | 使用说明 | 命令、基线、卡点 |

`train_subject()` / `evaluate_subject()` 接收 `RecordingLike`，不接收 EDF 路径。
这样：

- 单元测试可以注入内存 mock，不需要 mne/EDF；
- 入口 `main` 负责“文件 → Recording”，业务函数保持纯；
- 将来换数据源（LSL、NPZ、数据库）只改入口适配器，不动训练逻辑。

## 2. 允许的依赖矩阵

| from \ to | `eeg_core` | `eeg_app` | `training` | `scripts` |
| --- | --- | --- | --- | --- |
| `eeg_core` | ✅ | ❌ | ❌ | ❌ |
| `eeg_app` | ✅ | ✅ | ❌ | ❌ |
| `training/pipeline.py` | ✅ | ❌ | ✅ | ❌ |
| `training/train.py`、`evaluate.py` | ✅ | ✅（只在 `main` 内） | ✅ | ❌ |
| `scripts` | ✅ | ✅ | 视情况 | ✅ |

这张表由 [tests/unit/core/test_layering.py](../../tests/unit/core/test_layering.py) 自动检查：
core 不能 import app/training/scripts；app 不能 import training/scripts；`training/pipeline.py`
不能 import app；入口的 app import 不能出现在模块顶层。

## 3. 三条边界

### 3.1 契约边界（core 内部）

`EEGChunk`、`WindowRange`、`QualityReport`、`DecisionFrame`、`ModelInputSpec`、`ReferenceMarker`
都是 frozen dataclass。跨模块只传这些盒子；不要传裸 dict 当契约。

### 3.2 IO 边界（app 内部）

- 文件、mne、线程、时钟、Qt、CSV 全部留在 `eeg_app`。
- `Recording` 是 app 层的“整条记录”，不是契约；`EEGChunk` 才是契约。
- 训练层用 `RecordingLike` 协议，不依赖 `Recording` 类本身。

### 3.3 组合边界（入口）

`main()` / `app.py` / `runtime` 的组装函数是唯一允许“同时认识两边”的地方：

```python
# training/train.py 的组合根
from eeg_app.sources.input import load_edf   # 只在函数内

recording = load_edf(path)                   # app: 文件 → Recording
spec, json_path = train_subject(             # training: Recording → 模型包
    subject, recording=recording, train_file=..., config=...
)
```

业务函数 `train_subject()` 不知道 EDF 存在；它只看到 `RecordingLike`。

## 4. 运行时链路 vs 训练链路

### 运行时（应用层编排）

```text
app.sources.ReplaySource
  → EEGChunk
  → core.processing.FilterBank        # A: 质量/参考/滤波
  → core.processing.windows/features  # B: 分窗/18 维
  → core.decoding.ModelPackage        # B: 分数
  → core.decoding.DecisionEngine      # B: 六状态
  → DecisionFrame
  → app.outputs / app.ui
```

### 训练（离线）

```text
app.sources.input.load_edf            # 组合根
  → Recording
  → training.pipeline.build_feature_dataset   # 纯
      → core.processing.FilterBank
      → core.processing.windows/features
  → core.decoding.fit_lda
  → weights.npz + model.json
```

**注意**：两条链路共用 `core.processing` 与 `core.decoding`，不是两套实现。
训练/推理一致性靠“同一份 FilterBank + 同一份 features + `pipeline_version`”，
不是靠“看起来差不多”。

## 5. 代码放哪：一张判断表

| 你要加的东西 | 放哪 | 例子 |
| --- | --- | --- |
| 新的契约字段/对象 | `core/contracts` | 新 `DecisionState`、新 `ModelInputSpec` 字段 |
| 新的信号处理/特征 | `core/processing` | 新滤波器、CSP、频带功率比 |
| 新的分类器/推理/决策 | `core/decoding` | 逻辑回归、SVM、HMM 平滑 |
| 新文件格式/设备/回放 | `eeg_app/sources` | LSL、NPZ、BrainFlow |
| 会话/缓冲/队列 | `eeg_app/runtime` | 环形缓冲、过载暂停 |
| 界面/绘图 | `eeg_app/ui` | 波形、预测轨、火柴人 |
| 存档/导出 | `eeg_app/outputs` | JSONL、CSV、manifest |
| 离线训练管线 | `training` 纯模块 | pipeline、mock、fit 循环 |
| 训练/评估 CLI | `training/train.py`、`evaluate.py` 的 `main` | argparse、路径解析 |
| 一次性数据运维 | `scripts` | 下载、校验、导出 lock |

## 6. 常见反模式

| 反模式 | 为什么错 | 正确做法 |
| --- | --- | --- |
| `core` import `mne` / `Path.read_text` | 底层被 IO 绑死，无法单测/打包 | 放 `eeg_app/sources`，core 只吃数组/契约 |
| `core` import `eeg_app` | 依赖倒置，core 不能独立 | core 定义协议/契约，app 实现适配 |
| `app` 里写滤波/特征 | 训练/运行时两套实现，静默漂移 | 调 `core.processing` |
| `training/pipeline.py` import `Recording` | 训练管线被 EDF 绑死 | 用 `RecordingLike` 协议 |
| `training/train.py` 顶层 import `load_edf` | 模块导入即依赖 mne/IO | 只在 `main()`/组合根内 import |
| `ui` 直接调 `FilterBank` | 界面绕过 runtime，质量/预热状态对不上 | UI 只消费 `DecisionFrame`/波形数据 |
| 在 `app` 里构造契约对象 | 同一对象两处校验，规则漂移 | 由 core 构造/校验，app 只传参 |

## 8. 怎么验证分层没破

```powershell
.\.venv\Scripts\python.exe -m pytest tests\unit\core\test_layering.py -q
.\.venv\Scripts\python.exe -m pytest -q
```

`test_layering.py` 用 AST 扫 import：

- `eeg_core/**/*.py` 不能出现 `eeg_app`、`training`、`scripts`；
- `eeg_app/**/*.py` 不能出现 `training`、`scripts`；
- `training/pipeline.py` 不能出现 `eeg_app`；
- `training/train.py` / `evaluate.py` 的**顶层**不能出现 `eeg_app`（函数内组合根可以）。

这条测试比“口头约定”可靠：谁把 `mne` 塞进 core，CI 先红。
