# 接口约定 1.0（字段表）

> 版本 **1.0**（未冻结）· 代码在 `src/eeg_core/contracts/` · 表中每个字段都能在对应 dataclass
> 里找到同名属性；改字段时表和代码一起改，否则以代码为准并在当次提交里补表。

## 0. 六个文件各管什么

| 文件 | 放什么 | 不放什么 |
| --- | --- | --- |
| `frames.py` | 输入侧数据：`EEGChunk`、`WindowRange`、`SourceInfo`；统一异常 `ContractError` | 输出结构、协议、配置 |
| `outputs.py` | 输出侧数据：`QualityReport`、`DecisionState`、`Scores`、`DecisionFrame`、`utc_now_iso` | 输入块、协议 |
| `events.py` | 标注与事件：`ReferenceMarker`、`ResetReason`、`SessionState`、`RuntimeEvent`、`IntentEvent` | 决策、配置 |
| `model.py` | 模型包规格：`ModelInputSpec`、`IncompatibleModelError`、`FEATURE_LAYOUTS` | 权重读写、分类器实现 |
| `protocols.py` | **唯一的接口**：`DataValidator` + 参考实现 `ChunkStreamGuard` | 数据源/解码器/存档插座（纪律：不提前抽象） |
| `config.py` | 全局参数唯一出处：`AppConfig` + `DEFAULT_CONFIG` | 业务逻辑、校验规则 |

所有数据盒子都是 `@dataclass(frozen=True)`：构造即校验，之后改不动。

## 3. 三条通用规则

1. **一切冻结**：上面所有盒子都是 `frozen`；流水线中途改数据会直接抛 `FrozenInstanceError`。
2. **一个异常**：数据不合规统一抛 `ContractError`（`ValueError` 子类）；只有场景子类
   `IncompatibleSourceError`（带 `reasons`）和 `ChunkSequenceError` 用于区分场景。
3. **不提前抽象**：`protocols.py` 只有一个校验器接口。数据源、解码器、存档等插座等出现
   「离线文件」和「在线实时」两套实现时再加。

数据源的约定暂以 `ChunkStreamGuard` 为准（写适配器时在测试里挂一行）：
首块 `seq=0` 且 `discontinuity=True`；之后 `seq` 严格 +1；未标间断的块 `start_sample` 必须等于上一块的
`end_sample`；`recording_id`、采样率、通道表、通道类型不得中途变化；**块长不限**（T05 要测的就是这个）。

### 3.1 A → B 的交付边界：干净的 `EEGChunk`（2026-11-02 起）

在线路径上 B 不接触原始信号；训练时 B 仍要读 EDF，但滤波与质量判定必须调用 A 的同一份实现（`filters.py` / `quality.py`），不得另写一套。A 交出的块必须已经**滤波**且**判定过质量**，同时仍是本文件 §1 的契约对象：

1. **已滤波**：`filters.py` 提供有状态的 `FilterBank`（四阶 Butterworth SOS、因果、块间传状态、遇 `ResetReason` 清空重预热）。输入一块 `EEGChunk`，输出 8–13 Hz 与 13–30 Hz 两路数组；`EEGChunk` 本身只承载一路信号，**两路频带不是两个块**，不要复制 `seq` 造伪块。B 只调用 `FilterBank`，不重写滤波。
2. **已判质量**：质量结论用 `QualityReport` 单独给出（有窗时填 `window`），不改 `EEGChunk` 的任何字段。
3. **不变的部分**：单位伏、通道顺序、采样率、`seq`、`start_sample`、`discontinuity` 与 §1 完全一致；块内没有标签。
4. **可追溯**：训练与运行时共用同一份滤波与质量实现；模型包记录该实现的规格指纹（阶数、频带、是否因果、SOS 指纹、质量原因码集合），启动时比对不一致就拒绝运行。

B 侧禁止：再次滤波、把未来样本纳入特征、让参考标注进入解码路径、复制 A 的滤波或质量代码。谁改 `ProcessingConfig` 里的滤波或质量部分，谁负责同步模型包中的指纹。

**生效条件**：`FilterBank` 已落地（`processing/filters.py`，`process(chunk)` 返回含 `quality`、`band_8_13_hz`、`band_13_30_hz`、`ready`、`status` 的字典）；训练与运行时都调用它，`app.py` 组装时负责 µV → V 换算。

### 3.2 采样与标注的强制规则（2026-11-03 起）

1. **`samples` 只放生理通道**：脑电、EOG、EMG 这类物理量才进 `samples`，单位一律伏。
   设备的 trigger/stim/TTL 通道（值通常是 0/1）**不得混进来**——它们进 `ReferenceMarker`，
   并在 `channel_types` 里标明类型。混进来的后果是“单位伏”和“通道表”同时失真。
2. **秒 → 样本号统一四舍五入**：`round(onset_sec * sample_rate_hz)`，不要一半用 floor、
   一半用 round；否则同一段标注在两台机器上差一个样本，评估对不齐。
3. **质量阈值的单位是微伏 / 秒**：`ProcessingConfig.amplitude_limit_uv`、
   `flatline_sec`、`flatline_tolerance_uv` 分别是 µV、秒、µV；`app.py` 组装时乘 `1e-6`
   转成伏再传给 `QualityChecker`，换算只做一次，流水线中途不再换。
4. **参考策略来自固定词表**：`SourceConfig.reference_policy` 只能取 `REFERENCE_POLICIES`
   里的值；首版用 `model_channel_average`（由 A 的 `FilterBank` 实现，当前只支持这一种）。
   训练必须调用同一份实现，实际取值写进模型包。

## 4. 错误对照

| 异常 | 什么时候 | 调用方做什么 |
| --- | --- | --- |
| `ContractError` | 任一盒子字段不合规 | 当作输入不可用，不猜不修 |
| `IncompatibleSourceError` | 记录与模型要求不符（`check_compatible`） | 阻止运行，显示全部原因（T02） |
| `ChunkSequenceError` | 块序列跳号/缺口/重叠/换元数据 | 适配器 bug，测试阶段就该被抓到 |
| `IncompatibleModelError` | 模型包与记录或运行配置不符（`ModelInputSpec.check_compatible`） | 阻止运行，显示全部原因（T02） |
| `ConfigError` | 配置越界或组合不成立 | 启动即失败，不带病运行 |

## 5. 改契约的流程

1. **结构或语义变更**（加/删字段、改单位、改时间口径、改枚举取值）：改 `CONTRACT_VERSION`，
   同步本表与 `docs/05`，再改两边代码；**纯数值调整**（门限、有效期、质量阈值）不升版本，
   只通过 `AppConfig.config_hash` 写进 manifest 与运行日志；
2. 契约由 A 合入，改前通知 B/C/D；
3. 文档与代码不一致时以代码为准，并在当次提交里补表；
4. 冻结后只允许“加法”：新字段必须给默认值，旧产物仍能读；删除或改名一律升大版本。
