## 1. 一句话：契约是干什么的

四个人各写一块程序，中间要交接数据。契约就是交接时用的**模具**：数据必须长成这个样子，
不合规的在边界上就被拦下来，不会悄悄流到下一环变成难查的 bug。

契约负责四件事：

1. **统一格式**：同样叫"一块脑电"，在 A、B、C、D 手里必须长得一模一样。
2. **统一单位与时间**：伏、样本编号，不靠口头约定，也不靠墙上时钟。
3. **隔离标签**：模型只能看脑电，看不到答案（T03 要验的就是这个）。
4. **可追溯**：版本号 + 配置指纹，出了问题能回到当时那一套参数。

## 2. 数据怎么流动

```
EDF 文件（data/eegmmidb/S001/S001R04.edf）
   │  读取、单位换算（µV → V）、打面单
   ▼
【供数块 EEGChunk】每块约 50 ms（160 Hz 下 8 个样本）
   │  逐块检查：编号连续、样本首尾相接（ChunkStreamGuard）
   ▼
【质量检查】→ 【质量报告 QualityReport】不合格就 invalid，并重置状态
   │
   ▼
【因果滤波】状态跨块保留（滤波参数在 config）
   │
   ▼
【观察窗 WindowRange】2 s 窗、250 ms 步长，网格对齐
   │
   ▼
【特征】对数方差 → 【分类】收缩 LDA → 决策
   │
   ▼
【DecisionFrame】逐窗决策结果（已定义，还没人产出）
   │
   ├─ 界面（C）：波形、时间轴、火柴人
   └─ 存档（D）：decisions.jsonl / events.csv / runtime.jsonl / manifest.json / summary.json

另一条线：参考标注 ReferenceMarker 只给"参考轨"和评估用，不进入解码器。
全局参数：AppConfig（config.py）是唯一出处，谁都不许另写默认值。
```

## 4. 输入侧契约

### 4.1 SourceInfo：记录的"档案卡"

一条记录进门时先登记：多长、多少通道、采样率多少、参考方式是什么。

| 字段 | 类型 | 必填 | 含义 | 例子 |
| --- | --- | --- | --- | --- |
| `source_id` | 字符串 | 是 | 数据从哪来 | `physionet-eegmmidb` |
| `recording_id` | 字符串 | 是 | 哪条记录 | `S001R12` |
| `sample_rate_hz` | 浮点 | 是 | 每秒多少点 | `160.0` |
| `channel_names` | 字符串元组 | 是 | 通道顺序，和样本的行顺序一一对应 | `("FC3", "Cz", ...)` |
| `reference` | 字符串或 `None` | 否 | **文件里写的**参考方式；`None` 表示文件没写 | `None` |
| `subject_id` | 字符串或 `None` | 否 | 受试者编号 | `S001` |
| `run` | 字符串或 `None` | 否 | 记录类型（4/8/12） | `"12"` |
| `n_samples` | 整数或 `None` | 否 | 记录总样本数；`None` 表示未知，**不估算** | `16000` |

**重要区别**：`SourceInfo.reference` 是"文件里写了什么"，`config.source.reference_policy` 是"我们自己打算怎么重参考"。
PhysioNet 记录通常没有写明参考方式，所以前者是 `None`（显示为"未提供"）；**不要拿后者去核对前者**，否则每条真实记录都会被判不兼容。

可用方法：

| 方法 | 作用 |
| --- | --- |
| `reference_label` | 给人看的参考方式：有就原样返回，没有就返回 `"未提供"` |
| `duration_sec` | 总时长；`n_samples` 未知时返回 `None`，不猜 |
| `check_compatible(...)` | 按模型要求核对这条记录，见下 |

**`check_compatible` 怎么用**：传入模型要求的通道、采样率、参考方式，不通过时**一次性列出全部原因**并抛
`IncompatibleSourceError`（T02 要求"开始前阻止，说明原因，不猜测修正"）。

```python
info.check_compatible(
    required_channels=cfg.source.model_channels,   # 9 个模型通道
    sample_rate_hz=cfg.source.sample_rate_hz,      # 160 Hz
)
```

采样率比较有 1e-3 Hz 的浮点容差；缺通道、采样率不符、参考方式写不一致，都会被拒绝。**它不会自己补通道、重采样或猜参考。**

### 4.2 EEGChunk：一块脑电

一块 = 一小段连续样本，外加一张面单。**块本身不含任何标签、试次编号或标注时间表**。

| 字段 | 类型 | 默认 | 含义 |
| --- | --- | --- | --- |
| `source_id` | 字符串 | 必填 | 数据来源 |
| `recording_id` | 字符串 | 必填 | 记录编号 |
| `seq` | 整数 ≥ 0 | 必填 | 本记录内第几块，从 0 开始 |
| `start_sample` | 整数 ≥ 0 | 必填 | 本块第一个样本是整条记录的第几个点 |
| `sample_rate_hz` | 浮点 > 0 | 必填 | 采样率 |
| `channel_names` | 字符串元组 | 必填 | 通道顺序；**顺序就是样本的行顺序**，契约不排序、不改名 |
| `channel_types` | 字符串元组或 `None` | `None` | 每个通道的物理量类型；不填就是全 `"eeg"`；数量必须和通道表一致 |
| `samples` | 二维浮点数组 | 必填 | 形状 `(通道数, 样本数)`，单位**伏** |
| `released_monotonic_ms` | 浮点 ≥ 0 | 必填 | 这块交给下游的时刻（会话单调时钟，毫秒），只用来量延迟 |
| `discontinuity` | 布尔 | `False` | `True` = 新记录边界或已知间断 |
| `schema_version` | 字符串 | `"1.0"` | 契约版本，不匹配直接拒绝 |

构造时自动做的检查（任何一条不满足就抛异常，不会"凑合"）：

- 版本必须是 `"1.0"`；记录标识不能为空；`seq`、`start_sample` 必须是非负整数（布尔和浮点都不收）。
- 采样率必须大于 0 且是有限数。
- 通道名必须非空、不重复；两边空白会被去掉。
- 样本必须是二维浮点数组，行数等于通道数，列数至少 1。
- 样本会被**拷贝成只读**的 `float64` 数组：交出去之后，上游再改自己的缓冲区，也改不了已经发出的块。
- **NaN / Inf 原样放行**：这是刻意的，T07 要注入异常让质量层判 `invalid`；契约不做静默清洗，也不把坏数据伪装成好数据。

不用记字段也能用的派生信息：

| 属性/方法 | 作用 |
| --- | --- |
| `n_channels` / `n_samples` / `shape` | 通道数 / 样本数 / `(通道数, 样本数)` |
| `end_sample` | 本块之后第一个样本的编号（左闭右开的右端） |
| `start_t_sec` | 首样本的源时间 = `start_sample / 采样率` |
| `source_t_sec` | 本块末尾的源时间边界 = `end_sample / 采样率`（和决策的 `source_t_sec` 同一口径） |
| `duration_sec` | 本块覆盖的时长 |
| `unit` | 物理单位，恒为 `"V"` |
| `chunk_id` | 可排序的块标识，如 `S001R12/000042` |
| `channel_index(名字)` | 按通道名取行号；没有这个通道抛 `KeyError` |
| `has_non_finite()` | 是否含 NaN / Inf |
| `metadata()` | 不含样本的元数据字典，可直接写进 manifest 或运行日志 |

两条使用注意：

- 块是**只读**的，也不能当字典的键（不可哈希）；要比较两块是否相同，直接 `==`。
- 比较会连 `released_monotonic_ms` 一起比，所以"内容相同但释放时刻不同"的两块不相等。

### 4.3 ReferenceMarker：原始标注

这是"参考答案"，**只给参考轨和评估用，绝不进解码器**（PRD §5.3 的标签隔离，T03 验证）。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `recording_id` | 字符串 | 属于哪条记录 |
| `onset_sample` | 整数 ≥ 0 | 标注从第几个样本开始 |
| `label` | 字符串 | 记录里的原始标签，如 `T0` / `T1` / `T2`；**不做类别映射** |
| `duration_samples` | 整数或 `None` | 持续多少样本；没给就是 `None` |

方法：`end_sample`（没给时长就是 `None`）、`onset_t_sec(采样率)`、`covers_sample(样本号)`（没给时长时返回
`None` 表示"不知道"，不当成覆盖）。

**为什么标签不放进 EEGChunk**：放进去，解码器就同时拿到了数据和答案，T03"移除标签后预测必须一致"直接失效。
所以标注走单独一条线，连类型都不一样——解码器拿到的对象上没有 `markers` 这个属性。

## 5. 中间层与结果契约

### 5.1 WindowRange：观察窗

模型不是看 50 ms 的块，而是看最近 2 秒的窗。窗口用样本编号描述，左闭右开。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `sample_rate_hz` | 浮点 > 0 | 采样率，用来把样本号换算成秒 |
| `start_sample` | 整数 ≥ 0 | 窗口第一个样本 |
| `end_sample` | 整数 > `start_sample` | 窗口之后第一个样本（右端） |

四条必须遵守的规则：

| 规则 | 具体含义 | 怎么检查 |
| --- | --- | --- |
| **网格固定** | 起点锚定记录的第 0 个样本，`start = 第几个窗 × 步长` | `from_grid_index(...)` 生成、`is_aligned(步长)` 复核 |
| **必须完整** | 窗口结束不能超过已经收到的有效样本，不许用未来样本补 | `is_complete(已收到的右端)` |
| **不许跨断点** | 整个窗口必须落在同一段连续有效数据里 | 由产窗逻辑保证，间断后宁可不产窗 |
| **先预热** | 该段数据连续有效满 3 秒（480 个样本）后才出第一个窗 | 由产窗逻辑保证 |

数字对照（160 Hz）：

- 2 秒窗 = **320** 个样本；250 ms 步长 = **40** 个样本；3 秒预热 = **480** 个样本。
- 例：第 1000 个样本处发生间断。网格上 1040 就能当起点，但那时还没满 3 秒预热；第一个合法窗口是
  `[1160, 1480)`——起点对齐网格（29 × 40），末端满足预热。

其他方法：`n_samples`、`start_t_sec`、`source_t_sec`（窗口末端时间）、`duration_sec`、`contains_sample(样本号)`、
`overlaps(另一个窗)`（相邻不算重叠）、`is_aligned(步长, 锚点=0)`。

### 5.2 QualityReport：这个窗干不干净

| 字段 | 类型 | 默认 | 含义 |
| --- | --- | --- | --- |
| `valid` | 布尔 | 必填 | 能不能用 |
| `reasons` | 字符串元组 | `()` | 不能用的原因，只能是下面六个码 |
| `bad_channels` | 字符串元组 | `()` | 哪些通道有问题 |
| `window` | `WindowRange` 或 `None` | `None` | 窗口级检查带上；块级快速检查没有窗口 |

六个原因码是固定的，界面、CSV、测试都按这些字符串断言，不接受同义词：

| 原因码 | 中文意思 | 对应 PRD §6.2 的检查 |
| --- | --- | --- |
| `non_finite` | 出现 NaN / Inf | 非有限数值 |
| `missing_channel` | 必需通道缺失 | 必需通道缺失 |
| `sample_jump` | 样本编号跳变 | 样本编号跳变 |
| `interval_error` | 采样间隔异常 | 采样间隔异常 |
| `flatline` | 明显常量段 | 明显常量段 |
| `amplitude` | 幅值异常 | 异常幅值 |

互斥规则（构造时强制）：合格不能带原因和坏通道；不合格必须至少有一个原因。

用法：`QualityReport.ok(window)`（合格）、`QualityReport.failed(("non_finite",), bad_channels=("C3",), window=window)`（不合格）。

**质量阈值本身还没定**：PRD 只写了"依据训练与验证记录制定"，没有给数字，所以配置里暂时没有这几项；
B 在验证阶段定下来之后补进 `config.py`，补的时候要升契约版本。

### 5.3 reset 语义：脏了以后从哪重新开始

这是三个中间层类型里最容易出隐蔽错误的一个。**忘了重置，滤波器会把断点前后的样本算成一段连续信号，
结果看起来完全正常，但错得没边。**

触发原因（`ResetReason`，字符串枚举，可直接写进 `runtime.jsonl`）：

| 原因 | 什么时候用 | 必须清掉什么 |
| --- | --- | --- |
| `session_start` | 新会话开始 | 全部样本相关状态：滤波状态、未完成窗口、预热计数、候选确认、当前连续判定 |
| `discontinuity` | 块上标了 `discontinuity=True`（新记录或间断） | 同上 |
| `quality_invalid` | 质量检查不合格 | 同上；受影响通道不能继续参与后续窗口 |
| `pause_resume` | 用户暂停后继续 | **不清**滤波状态和历史（数据没断），只作废候选确认，防止重复发布暂停前的窗 |

实现约定：所有有状态的流式组件（滤波器、窗器、特征器、解码器）都实现 `StreamConsumer` 的
`reset(reason)`；运行时会话控制器在交出下一块**之前**调用；方法必须幂等（重复调用没问题）且不抛异常。

> 注意：`reset` 目前是"协议 + 文档约定"，还没有 `Decoder` 去实现它。`Decoder` 将来继承
> `StreamConsumer`，这条才真正闭环。

### 5.4 DecisionFrame：逐窗结果

一个更新点的完整结论：**证据窗 + 质量 + 状态 +（可选）分数 + 溯源信息**。界面只渲染它，
存档只写它，评估只比它。

六种状态（`DecisionState`，字符串枚举，可直接写 JSON）：

| 状态 | 含义 | 要窗口？ | 要分数？ | 要 intent？ |
| --- | --- | --- | --- | --- |
| `warming_up` | 历史不足（刚启动或刚重置） | 不要 | 不要 | 不要 |
| `idle` | 模型学到的"休息"类别 | 要 | 要 | 不要 |
| `left_hand` | 左手运动想象 | 要 | 要 | 要，且等于本体 |
| `right_hand` | 右手运动想象 | 要 | 要 | 要，且等于本体 |
| `uncertain` | 数据合格但门限/时间一致性没过 | 要 | 要 | 不要 |
| `invalid` | 质量不合格或流中断 | 可有可无 | 不要 | 不要 |

**低分不能直接转成 idle**：没过门限就是 `uncertain`，这是 PRD 的硬规则。

字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `session_id` | 字符串 | 会话标识，运行时生成（如 `demo-20261016-001`） |
| `recording_id` | 字符串 | 记录编号 |
| `seq` | 整数 ≥ 0 | 会话内第几个更新点 |
| `decision_id` | 字符串（派生） | `session_id/000048`，不单独存，避免和序号对不上 |
| `decision_state` | 六状态枚举 | 见上表 |
| `intent` | 枚举或 `None` | 只有左右手才非空，且必须等于状态 |
| `scores` | `Scores` 或 `None` | 三状态分数（0~1、有限、不要求和为 1） |
| `score_type` | 字符串 | 默认 `uncalibrated_probability` |
| `quality` | `QualityReport` | 质量结论 |
| `window` | `WindowRange` 或 `None` | 证据窗 |
| `source_t_sec` | 浮点 ≥ 0 | 窗口末端时间；有窗口时必须等于窗口的 `source_t_sec` |
| `sample_rate_hz` | 浮点 > 0 | 采样率；有窗口时必须与窗口一致 |
| `generated_at_utc` | 字符串 | UTC 的 ISO 时间，如 `2026-10-16T07:00:12.080Z` |
| `emitted_monotonic_ms` | 浮点 ≥ 0 | 会话单调时钟（毫秒），只用来算延迟 |
| `model_id` | 字符串 | 模型包标识 |
| `pipeline_version` | 字符串 | 处理链版本 |
| `config_hash` | 字符串 | 配置指纹（见 7.3） |
| `valid_for_ms` | 整数 > 0 | 有效期，默认 750 |
| `schema_version` | 字符串 | 契约版本 1.0 |

构造时强制的规则：

- `warming_up` 不能带窗口、分数、intent；`invalid` 必须带**不合格**的质量报告，窗口可有可无。
- 其余四种状态必须带窗口和分数，质量必须合格；`intent` 只允许出现在左右手上。
- `decision_state` 必须是枚举，不能传字符串（防止拼错状态名）。
- 有窗口时，采样率和 `source_t_sec` 必须和窗口一致。
- 分数必须在 0~1 之间且有限；`generated_at_utc` 必须是 UTC 的 ISO 格式。

序列化：

- `to_dict()` 的字段顺序与 PRD §7.2 的 JSON 示例一致，窗口缺失时两个样本字段为 `null`。
  `quality` 除了 `valid`、`reasons`，还多带一个 `bad_channels`（PRD 示例没有，但有用）。
- `to_json()` 输出单行 JSON，可直接写 `decisions.jsonl`；**不允许出现 NaN / Infinity**，
  写不出来就直接抛错，不会写出坏文件。
- `utc_now_iso()` 是统一的时间串生成入口，别自己拼格式。

示例（左手，与 PRD 示例同构）：

## 6. 行为协议

### 6.1 DataSource：数据源插座

任何数据源（第一版是 EDF 回放，以后可能是串口、TCP、LSL）要实现四个东西：

| 成员 | 作用 |
| --- | --- |
| `info` | 返回档案卡 `SourceInfo`，可以反复读 |
| `read_chunk()` | 返回下一块 `EEGChunk`；读完了返回 `None`，之后一直返回 `None` |
| `close()` | 收摊；可重复调用 |
| `with` 支持 | `with 源 as s:` 退出时自动 `close()` |

六条必须遵守的纪律（`ChunkStreamGuard` 能自动检查前四条的后半部分）：

1. **一个实例只服务一条记录**。换记录就换实例，`seq` 从 0 重新开始。
2. **块必须连续**：`seq` 严格 +1；没标间断时，`start_sample` 必须等于上一块的 `end_sample`。
3. **块长可以变**：8 个样本一块、10 个样本一块都合法（T05 就靠这个测"换块长结果不变"）。
4. **间断必须标**：丢包、暂停后不补齐、重连，都要标 `discontinuity=True`，不许假装连续。
5. **只给过去的样本**：调用方拿不到未来样本，也不能用整文件预先算好的特征。
6. **关闭后报错**：`close()` 之后调 `read_chunk()` 抛 `SourceClosedError`。

### 6.2 MarkerSource：参考标注插座

只有一个 `markers` 属性，返回按 `onset_sample` 升序排列的 `ReferenceMarker` 元组。

它和 `DataSource` 通常是同一个适配器对象实现，但**不允许注入解码路径**：解码器只接收 `DataSource`/`EEGChunk`，
类型上就拿不到 `markers`（T03）。

### 6.3 ChunkStreamGuard：切分检查器

逐块"记账"，专门抓适配器的切分错误。用法：

```python
guard = ChunkStreamGuard(source.info)
while (chunk := source.read_chunk()) is not None:
    guard.accept(chunk)
```

检查什么：

| 检查项 | 违反时 |
| --- | --- |
| 首块 `seq=0` 且 `discontinuity=True` | `ChunkSequenceError` |
| `seq` 严格 +1，不跳号不重复 | 报出期望值和实际值 |
| 未标间断时样本首尾相接 | 报出"缺口 N 个样本"或"重叠 N 个样本" |
| 标了间断的块不能往回跳 | 报错 |
| `recording_id`、采样率、通道表、通道类型中途不变 | 报错 |

**它不检查块长**——这是刻意的，块长本来就可以变。它也不检查"块内样本数是否等于 50 ms"，因为末块和调度抖动
都是合法的。

### 6.4 Decoder / ResultSink：还没写

- `Decoder`（计划）：`reset(reason)` + 接收窗口与质量报告、产出 `DecisionFrame`。
  输出类型已经定好了（5.4），输入到底给"窗口"还是"特征向量"还没定——这决定 B 的处理链怎么切，
  要先和 B 对一下再写。
- `ResultSink`（计划）：结果出口，JSONL、CSV、内存回调都要能替换，且一个出口失败不能影响另一个。

`DecisionFrame` 已经不是缺口了；剩下的缺口见第 10 节。

### 7.2 组合校验（不只是单个字段）

- 步长不能大于窗口（否则窗口不重叠地跳着走）。
- 门限必须小于 1，且门限 + 领先差不能超过 1。
- 暂停阈值必须大于告警阈值。
- 验收刷新率不能高于目标刷新率。
- 模型通道数不能超过总通道数。
- 频带必须低频小于高频且大于 0。

### 7.3 配置指纹

`AppConfig.config_hash` 是全部字段的规范指纹（当前默认配置为 `aaaaac7304ec50eb`，16 位十六进制）。
同一份配置在任何机器上得到同一个值；任何一个参数变了它就会变。它要写进 manifest，也要进 `DecisionFrame.config_hash`。

`to_dict()` 给出可直接 JSON 化的字典（元组按数组写出）。

## 8. 出错了怎么办

| 异常 | 什么时候抛 | 调用方应该做什么 |
| --- | --- | --- |
| `EEGChunkError`（`ValueError` 子类） | 数据块、窗口、质量报告、标注的格式不对 | 当作"输入不可用"上报，不猜、不修 |
| `ConfigError`（`ValueError` 子类） | 配置字段越界或组合不成立 | 启动时就该失败，不要带病运行 |
| `SourceError`（`RuntimeError` 基类） | 数据源层面的错误 | 提示并结束会话或重试 |
| `SourceClosedError` | 关闭后继续读 | 代码 bug，修调用顺序 |
| `IncompatibleSourceError` | 记录与模型/配置不兼容，带 `reasons` 列表 | 阻止运行，把原因显示给用户（T02） |
| `ChunkSequenceError` | 块序列不合法 | 适配器 bug，测试阶段就该被 guard 抓住 |

> 命名说明：`EEGChunkError` 也用于窗口和质量报告的校验（历史命名），它实际上是契约包统一的值校验异常。

## 9. 几条硬规矩，和为什么

1. **单位只认伏。** EDF 读出来是微伏，由适配器乘 1e-6 换成伏；界面显示再乘 1e6。中间层绝不换算，
   否则"这个数是伏还是微伏"会变成每周都要排查的 bug。
2. **时间只认样本编号。** `第几个样本 / 采样率`。这样同一段数据怎么切块，窗口边界都一样（T05），
   也不受电脑卡顿影响。
3. **标签隔离。** 块里没有答案；标注走另一条线；解码器类型上拿不到标注（T03）。
4. **只读 + 拷贝。** 块交出去就冻结，上游改自己的缓冲区污染不了下游。
5. **坏数据放行、不洗白。** NaN 原样通过，由质量层判 `invalid`；契约不替你做决定。
6. **间断必须重置。** 标了 `discontinuity` 就清状态、重新预热，不许拼"看起来连续"的窗（T04、T07）。
7. **配置单一出处。** 下游不许另写默认值，否则同一次运行会出现两套参数。

## 11. 最小用法示例

```python
from eeg_core.contracts import (
    DEFAULT_CONFIG, ChunkStreamGuard, QualityReport, ResetReason,
    SourceInfo, StreamConsumer, WindowRange,
)

cfg = DEFAULT_CONFIG

# 1) 打开记录：先拿档案卡，再按模型要求核对
info: SourceInfo = source.info
info.check_compatible(
    required_channels=cfg.source.model_channels,
    sample_rate_hz=cfg.source.sample_rate_hz,
)

# 2) 逐块读取：编号/连续性由 guard 把关
guard = ChunkStreamGuard(info)
consumer: StreamConsumer = decoder          # 将来的 Decoder 实现本协议
consumer.reset(ResetReason.SESSION_START)

while (chunk := source.read_chunk()) is not None:
    guard.accept(chunk)

    if chunk.discontinuity:                 # 新记录或间断
        consumer.reset(ResetReason.DISCONTINUITY)

    # 3) 出窗（由 processing 按网格生成）→ 质量检查 → 决策
    window = WindowRange.from_grid_index(
        k, sample_rate_hz=cfg.source.sample_rate_hz,
        window_samples=320, hop_samples=40,
    )
    quality = QualityReport.ok(window)      # 或 failed(...)
    if not quality.valid:
        consumer.reset(ResetReason.QUALITY_INVALID)
```

（`decoder` 是占位：`Decoder` 协议还没写，输入形态待定。）

产出结果时这样写：

```python
from eeg_core.contracts import DecisionFrame, DecisionState, Scores, utc_now_iso

frame = DecisionFrame(
    session_id="demo-20261016-001",
    recording_id="S001R12",
    seq=48,
    decision_state=DecisionState.LEFT_HAND,
    sample_rate_hz=cfg.source.sample_rate_hz,
    source_t_sec=window.source_t_sec,        # 必须等于窗口末端时间
    generated_at_utc=utc_now_iso(),
    emitted_monotonic_ms=12080.0,            # 会话单调时钟
    model_id="S001-lda-v1",
    pipeline_version="1.0.0",
    config_hash=cfg.config_hash,
    window=window,
    intent=DecisionState.LEFT_HAND,
    scores=Scores(0.12, 0.76, 0.12),
)
line = frame.to_json()                       # 直接写 decisions.jsonl
```

## 12. 怎么改契约

1. **契约只由 A 合入**（README §4.3 的硬边界）；改之前先通知 B/C/D。
2. **改字段 = 升版本**：改 `CONTRACT_VERSION`，同步本文档与样例，再改双方代码。
3. **改默认参数**：先改 `config.py`，同步本文档第 7 节；`config_hash` 会自己变，不要手写死值。
4. **提交说明**写清"做了什么、为什么、怎么验证"。
5. **文档与代码不一致时以代码为准**，并在当次提交里改文档，不许拖。
