## 二、已完成

### 输入侧（`frames.py`）

- **`EEGChunk`**：身份、时间、形状、物理属性、通道、流级事件六组信息；单位伏、只读 `float64`、
  NaN 原样放行；派生 `chunk_id`、`start_t_sec`、`source_t_sec`、`end_sample`、`metadata()`。
- **`WindowRange`**：观察窗 `[start, end)`，网格锚定样本 0；`from_grid_index` / `is_aligned` /
  `is_complete` / `overlaps`。2 s = 320 样本，250 ms = 40 样本，预热 3 s = 480 样本。
- **`SourceInfo`**：记录档案卡 + `check_compatible()`（缺通道、采样率、参考方式一次报全，T02）。
- **`ContractError`**：契约包唯一异常；`IncompatibleSourceError` 带 `reasons`。

### 输出侧（`outputs.py`）

- **`QualityReport`**：`valid` + 6 个固定原因码 + `bad_channels` + 可选窗口。
- **`DecisionState`**：六种状态；`Scores`：三状态分数（0~1、不要求和为 1）。
- **`DecisionFrame`**：字段与 PRD §7.2 一一对应；六状态 × 窗口/分数/intent 组合在构造时强制；
  `to_json()` 单行、拒绝 NaN，可直接写 `decisions.jsonl`。

### 事件与重置（`events.py`）

- **`ReferenceMarker`**：参考标注，标签隔离（不进 `EEGChunk`、不进解码路径）。
- **`ResetReason`**：四种重置原因及各自要清什么（不抽象协议，按枚举执行）。

### 接口（`protocols.py`）

- **`DataValidator`**：唯一的接口，`validate(chunk) -> chunk`。
- **`ChunkStreamGuard`**：逐块检查 seq、首尾相接、间断标记、元数据中途不变；**不检查块长**（T05）。

### 配置（`config.py`）

- `AppConfig` + 5 组参数，默认值与 README §8 / PRD §6.1 对齐；组合校验；`config_hash`
  当前 `a5b79b8cf968dc34`（`preprocessing_hash` = `3c7e058192aaaf93`，契约 1.1 起不含 `channel_count`）。

### 验证

临时自检 **108 项**全部通过：布局与纪律（frozen、导出 27、未提前抽象）、块与序列、窗口、
档案卡与兼容检查、标注、质量、决策与 JSON、重置原因、配置回归。⚠️ **脚本在临时目录，未进仓库**。

### 2026-11-05 · mock 数据评分基线（假数据，不是真实结论）

**动机**：真实数据的标签噪声与个体差异会掩盖链路本身的 bug。用 ``training/mock.py`` 的合成记录
（T1/T2 在 8–13 / 13–30 Hz 上做左右不对称，答案已知）给整条链打分：分数低只可能是
质量 → 滤波 → 分窗 → 特征 → LDA → 决策 出了问题。

**工具**：``scripts/score_mock.py``（训练 seed 11 / 160 s，测试 seed 22 / 120 s，试次 4 s）：

* **窗口级**：走 ``build_feature_dataset``，只算整窗落在同一标注区间且过了 3 s 预热的窗；
* **决策级**：每 250 ms 一个更新点，把质量/预热/分数喂给 ``DecisionEngine``；``uncertain`` /
  ``invalid`` / 重新预热都算没答对，另报“有答案时答对多少”和动作确认延迟；
* **对照**：测试信号去掉类别差异（``class_effect=0``），分数应回到 1/3 随机水平。

**结果**（阈值与范围见上一节；clean 共 473 个窗，261 个可评分）

| 场景 | 窗口级 准确率 / 宏 F1 | 决策级 严格准确率 | 决策级 答案内准确率 | 伪迹表现 |
| --- | --- | --- | --- | --- |
| clean | 0.935 / 0.932 | 0.797 | 0.945 | invalid 0 块 / 0 点 |
| zero_effect（对照） | 0.322 / 0.255 | 0.272 | 0.321 | 18/20 个动作试次没有答案 |
| spike | 0.937 / 0.931 | 0.778 | 0.944 | 1 块、1 个决策点 invalid |
| flatline | 0.933 / 0.930 | 0.770 | 0.944 | 1 块、4 个决策点 invalid |
| nan | 0.937 / 0.931 | 0.778 | 0.944 | 1 块、1 个决策点 invalid |

- 类别平衡：idle 81 / left 90 / right 90 窗；每类 F1 idle 0.89 / left 0.94 / right 0.97。
- 决策级：261 个有标签点，idle 56 / left 83 / right 81 / uncertain 41；错误动作率 0.042；
  动作确认延迟中位 **2.25 s**（2 s 窗 + 连续 3 次确认，p90 2.75 s），20 个动作试次全部给出动作。
- 对照接近 1/3（准确率 0.322）→ 分数来自类别差异，不是标签泄漏或过拟合。

**怎么读**

- 窗级 0.93、答案内 0.945 说明特征与模型能学到已知的类别差异；**idle 是弱项**（F1 0.89），
  因为合成信号各通道相位独立、平均参考会给每窗带来约 ±0.5 的 log 方差抖动，idle 又夹在左右手中间。
- 严格准确率比窗级低约 0.14：41 个 ``uncertain`` 全部来自每次试次切换后的 3 次确认，
  **损失在决策逻辑，不在特征**；这也是 PRD 决策点口径会看到的真实代价。
- 伪迹场景只掉 1 块：质量门与重新预热工作正常，代价是 5–8 个决策点的 ``warming_up``。

**注意**：这些分数不能与真实数据的 0.462（五人宏 F1）比较——mock 是可分的教学数据，
真实数据要难得多。它是“链路是否自洽”的体检，不是性能结论。训练/测试用不同 seed（11 / 22），
噪声与相位独立，**没有样本重叠**；但两者来自同一个生成器，模型学到的终究是“10/20 Hz 正弦 +
左右增益”这个模拟器，高分不能外推到真实 EEG。
