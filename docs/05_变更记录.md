## 二、已完成（可以放心用）

### 输入侧

- **`EEGChunk`**：一块脑电，六组信息（身份、时间、形状、物理属性、通道、流级事件）。
  - 单位固定伏，样本只读 `float64`，构造即校验；NaN/Inf 原样放行（交给质量层判 `invalid`）。
  - 时间只由样本编号推：`start_t_sec`、`source_t_sec`、`end_sample`、`duration_sec`。
  - 派生 `chunk_id`（如 `S001R12/000042`）、`metadata()`（可直接写 manifest）。
- **`SourceInfo`**：记录档案卡；`check_compatible()` 一次列出缺通道/采样率/参考方式的全部原因（T02）。
- **`DataSource`**：数据源插座（`info` / `read_chunk` / `close` / `with`）+ 六条纪律。
- **`MarkerSource`**：参考标注单独一条线，解码器类型上拿不到（标签隔离，T03）。
- **`ChunkStreamGuard`**：逐块检查 seq、首尾相接、间断标记、元数据中途不变；**不检查块长**（T05）。

### 中间层

- **`WindowRange`**：观察窗，网格锚定样本 0（2 s = 320 样本，250 ms = 40 样本），
  `is_complete` / `is_aligned` / `overlaps` / `contains_sample`。
- **`QualityReport`**：`valid` + 6 个固定原因码 + `bad_channels` + 可选窗口；合格与原因互斥。
- **`ResetReason` / `StreamConsumer`**：4 种重置原因，每种要清什么写在文档里；`reset` 必须幂等。

### 结果侧

- **`DecisionFrame`**：逐窗结果，字段名与顺序和 PRD §7.2 的 JSON 示例一一对应。
  - 六状态 × 窗口/分数/intent 的合法组合在构造时强制；`invalid` ⇔ 质量不合格。
  - `decision_id` 由 `session_id/000048` 派生；`to_json()` 单行输出、禁止 NaN（可直接写 `decisions.jsonl`）。
- **`Scores`**：三状态分数，0~1、有限、不要求和为 1。
- **`utc_now_iso()`**：统一时间串入口。

### 配置

- **`AppConfig`**（只读）+ 5 组参数（数据源与回放、处理与特征、连续决策、运行时、界面），
  默认值与 README §8/PRD §6.1 逐条对齐；组合校验（步长≤窗口、门限+领先差≤1、暂停>告警等）。
- **`config_hash`**：全部字段的规范指纹，当前默认 `aaaaac7304ec50eb`，写 manifest 和 `DecisionFrame`。
